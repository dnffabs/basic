# M4 内存分块

M4 给栈、全局数据和堆分配点建立可引用的块。以固定的 `test_64` 为例，M4 找到 32 个栈块、12 个全局块和 1 个堆块。其中全局变量 `initialized_value` 位于 `0x404030`，对应的分析区间是 `[0x404030, 0x404040)`。区间的右端来自下一处分块边界，可能包含对齐填充。堆块则用调用 `malloc` 的指令地址标识。

## 输入与运行

支持 X86 和 AMD64 ELF。需要项目 Python 环境、64 位 Soufflé 和 GNU objdump。本机验证使用 Soufflé 2.5。M4 的规则和辅助脚本随项目保存，正常运行只读取当前项目和输入 ELF。

```bash
# 从 ELF 运行到 M4
PYTHONPATH=src .venv/bin/python -m bpa tests/fixtures/binaries/test_64 \
  --stage m4 -o outputs/test_64

# 复用已完成的 M3，同时读取它旁边的 m1/、m2/
PYTHONPATH=src .venv/bin/python -m bpa tests/fixtures/binaries/test_64 \
  --stage m4 --m3 outputs/test_64/m3 -o outputs/test_64
```

M4 校验 ELF 身份、M3 状态和上游文件摘要。复用时跳过 CFGFast 和 VEX 提取。可通过 `--souffle /path/to/souffle` 指定引擎。程序位置沿用 ELF VA。处理 PIE 时，在映射地址范围中匹配 VEX 的全局地址候选，只把推导出的地址还原为 ELF VA。原始常量及 M3 的 guard 均保存在原始 facts 中。

## 三类块如何产生

| 类型 | 默认算法 | 块的含义 |
| --- | --- | --- |
| 栈 | 以函数入口 SP 为零点，在块内跟踪赋值，在按固定次序构造的过程内生成树上传播偏移。收集非负偏移、负偏移取址、函数入口、调用时栈顶、push 和栈传参六类边界证据。 | 同一函数内将偏移排序，两侧保留无界区间。规则识别出的栈实参可额外生成调用点专属块。 |
| 全局 | 在 M1 全局区域内，从直接内存访问、传递地址常量、常量参与的地址运算、带比例索引的寻址中收集候选。用索引步长抑制重叠候选，然后加入各区域起止位置。 | 相邻边界形成左闭右开区间。与参考实现一致，排序后的相邻区域之间也可能产生间隔块。访问归属额外检查地址确实位于 M1 的全局区域。 |
| 堆 | 识别用户函数范围内直接调用已知 `malloc`、`calloc`、`realloc` 入口或其 PLT 项的指令。 | 每个静态调用点建立一个抽象堆块。同一调用在循环中执行多次仍对应同一个块。 |

Soufflé 负责偏移传播、边界推导、分配点识别和栈块匹配。Python 负责连接 M1–M3、用 objdump 辅助识别栈行为、构造传播树、整理区间和发布结果。采用 BPA-X 的 `normal` 栈和全局分块口径，规则版本及 MIT 许可见 [基线来源](../src/bpa/memory/baseline/README.md)。

## 读取产物

先读 `m4/manifest.json`，再从相对目录 `facts_dir` 读取制表符分隔、无表头的 `*.facts`。清单包含每张表的列名、行数、SHA256、上游 M3 清单摘要和基线版本。一次运行完整生成结果后才更新清单。

| 关系 | 主要字段及用途 |
| --- | --- |
| `mloc_sblk` | 块 ID、函数入口、偏移下界、偏移上界、下界有效、上界有效、调用点。有效标记为 0 表示该端无界。调用点为 0 表示普通块。 |
| `mloc_gblk` | 块 ID、ELF VA 下界、上界及有效标记。`mloc_gchk` 保留抑制重叠前的候选分段，`mloc_gcoarser` 在 normal 模式为空。 |
| `mloc_hblk` | 块 ID、分配调用点的 ELF VA。 |
| `local_block_boundary`、`global_chunk_boundary`、`global_block_boundary`、`heap_block` | 栈边界的指令与偏移、全局候选与保留边界的指令和地址、堆分配点。适合定位首次出现差异的位置。 |
| `tmp_reg_offset`、`tmp_reg_sblk_id`、`tmp_reg_func_arg_passing` | 块内临时变量的栈偏移、它可能关联的栈块、调用点传参信息。临时变量键为十进制基本块地址与块内编号，以 `_` 连接。 |
| `memory_access_block` | M3 访问种类、访问 ID、块类别、块 ID、偏移、访问位宽和偏移依据。直接全局访问和有栈偏移证据的访问可产生记录，复杂指针留待后续传播。 |
| `unmapped_access` | 仍缺少块归属的已建模 M3 访问，保留访问种类、访问 ID、地址表达式 ID 和位宽。 |

块 ID 需要和类别一起使用。访问键是 `(kind, access_id)`，普通 load 对应 M3 表达式 ID，store 和带 guard 的访问对应语句 ID。归属指向访问的起始地址，位宽以 bit 为单位。一条访问可能关联多个候选块。偏移依据 `direct` 和 `block_start` 都从块起点以字节计量，`entry_sp` 从函数入口 SP 计量，用于无下界的栈块。堆访问与分配点的连接留给后续指针传播。

## 与原版 BPA-X 对照

对照脚本对同一个 ELF 独立运行 BPA-X 的前端、预处理、分块和后处理，然后逐条比较集合。栈块按函数、偏移边界及有效位、调用点比较，全局块按范围及有效位比较，堆块按调用点比较。额外核对栈边界证据、去重后的栈边界、临时变量到栈块的关系、全局候选和保留边界，共八项。差集记录在 `comparison.json` 的 `only_ours`、`only_reference` 中。

```bash
PYTHONPATH=src .venv/bin/python tests/compare_m4_bpax.py \
  tests/fixtures/binaries/test_64 -o outputs/m4_check/test_64
```

可用 `--bpax-root`、`--reference-python`、`--readelf-bin` 指定参考环境。对照脚本当前要求参考输入的 ELF VA 和 mapped VA 相同。PIE 另用同一个二进制在两个映射基址下比较 ELF VA 分块，并核验已知全局地址。

| 固定样本 | 栈块 | 全局块 | 堆块 | 已关联 / 全部已建模访问 | 八项对照 |
| --- | ---: | ---: | ---: | ---: | --- |
| test_32 | 74 | 12 | 1 | 84 / 144 | 一致 |
| test_64 | 32 | 12 | 1 | 69 / 99 | 一致 |
| bzip2_64_O2 | 551 | 107 | 6 | 2215 / 5416 | 一致 |

这些数字针对当前固定二进制。重新编译后用脚本比较同一份 ELF 的双方产物。本阶段的栈传播沿基线生成树，分支条件和动态指针的精细求解留给后续分析。
