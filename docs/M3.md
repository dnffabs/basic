# M3：VEX 指令语义与 Datalog facts

M3 已实现：读取 M1、M2 的结果，按已有基本块提升为 VEX IR，输出后续分析可读取的 Datalog facts。本阶段记录指令行为，内存块划分交给 M4，定义与使用、指针传播和间接调用目标求解由后续阶段完成。

实现遵循 [M3 已确定约定](M3_DECISIONS.md)。当前支持小端 AMD64 和 X86，使用项目锁定的 angr/CLE/pyvex 9.2.173。

## 1. 处理过程

1. 校验 ELF 的 SHA256、M1 地址与加载信息，以及 M2 的 schema、架构和工具版本。
2. 读取 M2 的基本块地址、长度和机器指令。M3 不运行 CFGFast，不按函数范围重新切块，没有函数归属和有多个归属的块均保留。
3. 按 M1 的加载基址建立私有 angr 项目，将块位置从 ELF VA 转成 mapped VA 后提取 VEX。
4. 核对 VEX 提升长度、IMark 指令范围和 jumpkind 是否与 M2 相符，逐条生成语句、表达式和访问关系。
5. 关联 M2 的控制流与调用位置，保留原始栈效果，保存全局区域的重定位初始字节。
6. 检查事实类型、主键、引用和部分位宽约束，输出 facts、schema 与校验清单。

M2 和 M3 共用 `src/bpa/lifting.py` 中的显式参数：`opt_level=1`、`cross_insn_opt=True`、`strict_block_end=False`；`load_from_ro_regions`、`const_prop`、`collect_data_refs`、`skip_stmts` 均为 `False`，`traceflags=0`。这些值对应当前锁定版本原来使用的默认行为，现在写入 M2 options 和 M3 manifest。

旧 M2 文件没有显式提取参数时，按锁定版本的上述默认值处理，并在 manifest 标记 `m2_lift_options_explicit=false`；仍核对实际指令范围与 jumpkind。显式参数不一致时拒绝输入。

## 2. 运行方式

从二进制运行到 M3，自动生成 M1、M2 输入产物：

```bash
PYTHONPATH=src uv run --locked python -m bpa \
  tests/fixtures/binaries/test_64 --stage m3 -o outputs/m3/test_64
```

32 位程序将输入和目录改成 `test_32` 即可。

复用已有 M1、M2，不重新恢复 CFG：

```bash
PYTHONPATH=src uv run --locked python -m bpa \
  tests/fixtures/binaries/test_64 --stage m3 \
  --m1 outputs/m3/test_64/m1/binary.json \
  --m2 outputs/m3/test_64/m2/cfg.json \
  -o outputs/m3/reused_test_64
```

`--m2` 接受 `cfg.json` 文件路径，需要同时提供 `--m1`，并读取同目录的 `functions.json`。复制输入产物前会校验并提取，源文件保持原样。也可以只提供 `--m1`，此时会构建 M2 后继续提取。

## 3. 产物

```text
outputs/m3/test_64/
├── m1/binary.json
├── m2/
│   ├── functions.json
│   └── cfg.json
└── m3/
    ├── manifest.json
    ├── schema.json
    ├── schema.dl
    ├── block.facts
    ├── statement.facts
    ├── expression.facts
    ├── ...其余关系.facts
    └── diagnostic.facts
```

- `manifest.json`：schema `bpa.m3.v1`、输入 ELF 身份、M1/M2 文件哈希、加载基址、工具版本、提取参数、提取状态、逐关系行数及文件 SHA256。
- `schema.json`：全部 31 个关系的字段、类型、主键、外键，以及地址和常量约定。
- `schema.dl`：Souffle `.decl` 与 `.input` 声明，可以被后续 Datalog 规则包含。
- `*.facts`：UTF-8、制表符分列、无表头，空关系也创建文件。符号中的反斜杠、tab、换行和回车使用约定的转义；Python 读取接口负责还原。

输出先写入临时目录，再逐文件替换，最后发布 manifest。文件哈希用于检测中断或混合版本产物；这不是整个目录的一次原子替换。写入前保护输入 ELF 和相关输入文件，避免通过同路径、软链接或硬链接覆盖输入。

## 4. 关系与语义

完整列顺序以生成的 `schema.json` 为准。

| 类别 | 关系 | 保存的信息 |
| --- | --- | --- |
| 块和指令 | `block`、`block_function`、`instruction` | M2 块范围、提升长度、函数归属和机器指令 |
| 位置与身份 | `statement`、`expression` | 语句位置、所属机器指令、指令内顺序、表达式位宽与类型 |
| 临时变量 | `temporary`、`temporary_read`、`temporary_write` | 基本块内临时变量及其读写 |
| 寄存器 | `register`、`register_read`、`register_write` | guest-state 偏移、访问位宽、辅助名称、读写值 |
| 常量和运算 | `constant`、`operation`、`operand` | 原始位模式、完整 opcode、有序操作数 |
| 普通内存访问 | `load`、`store` | 地址与值表达式、访问位宽、字节序 |
| 条件内存访问 | `guarded_load`、`guarded_store` | guard、替代值、加载转换、源/结果位宽等 |
| 条件和块出口 | `branch`、`block_exit` | 条件跳转的 guard、目标表达式和 jumpkind |
| M2 控制转移 | `control_transfer`、`continuation`、`known_target`、`external_target` | 已知目标、外部符号、续点和未解析状态 |
| 调用关联 | `transfer_statement` | 调用/返回机器指令与其 VEX 语句的对应 |
| 初始边 | `cfg_edge`、`cfg_external_edge` | M2 边及其来源，保留 fake-return 等区别 |
| 初始内存 | `initial_memory` | M1 全局区域中的 CLE 重定位字节，每块最多 4096 字节 |
| 未建模与诊断 | `unmodeled_expression`、`unmodeled_statement`、`diagnostic` | 未支持的类型、原始表示及提取问题 |

主程序位置使用 ELF VA。VEX 常量按每次出现记录，保存位宽和固定宽度十六进制字符串，不按地址统一转换，支持超过 64 位的整数/向量位模式。语句和表达式共用确定性分配器，数值集合互不重叠，均为正数；类别由关系区分。临时变量使用 `(block, index)` 标识，不与表达式 ID 混用。

`statement.position` 是块内 VEX 顺序，从 0 开始；`statement.order` 是机器指令内顺序，IMark 为 0，其余语句从 1 开始。每个成功提升的块另外记录一条 `Terminator`，承载块出口目标表达式。表达式关联其所属语句，临时变量每次读取均有独立表达式，便于定位访问发生的位置。

ITE 以 `operation=ITE` 表示，操作数 0、1、2 分别为条件、真值、假值；不会提前合并真假分支。寄存器原始读写不应用 BPA-X 白名单，保留偏移和访问位宽，重叠访问仍需后续定义与使用分析处理。

`transfer_statement` 关联调用/返回机器指令内部的语句，包含计算、读取和写入；它不是“所有关联语句都是栈写入”的分类。调用压入返回地址、调整栈指针和返回读取等效果仍由实际读写事实表达。

`initial_memory.address` 是 ELF VA，保存的字节来自 CLE 重定位后的映射内存，其中指针可能为 mapped VA。M4 需要结合 M1 的基址、区域和重定位信息解释这些值，不能对所有机器字统一减加载偏移，也不能将全局区域直接当作已划分的对象内存块。

## 5. 后续阶段读取

```python
from bpa.vex import read_facts

raw = read_facts("outputs/m3/test_64/m3")
stores = raw.rows["store"]
statements = {row[0]: row for row in raw.rows["statement"]}
```

该读取接口只依赖 Python 标准库，不导入 angr、CLE 或 pyvex。它校验 schema、文件哈希、行数和事实引用。M4 可以结合同任务目录的 M1/M2 文件使用这些数据，并核对 manifest 的上游文件哈希。

提取接口位于 `bpa.vex.extractor.extract_vex(info, cfg_document)`，返回 `FactResult`，不直接写文件。`run_m3()` 负责阶段编排和文件发布。

## 6. BPA-X 对照

原始事实是正式产物；需要对照时再生成投影：

```bash
PYTHONPATH=src uv run --locked python -m bpa.vex.compat \
  outputs/m3/test_64/m3 -o outputs/m3/test_64/bpax
```

投影生成 BPA-X 风格的寄存器/临时变量/内存读写、一元/二元/ITE 表达式、常量、机器指令标记，以及 `binop_dl_exp`、`unop_dl_exp` 和有无符号转换关系。原始 opcode 不会被覆盖。`expression_origin`、`statement_origin` 保存对应关系，`generated_expression` 标识转换新增的位宽常量。

仅在投影中复现 BPA-X 白名单、按偏移翻译名称、忽略 ITE 条件、过滤 helper/guarded 操作，以及有无符号除法/比较的近似映射。超过 64 位的常量不进入该投影，原始层继续保留。投影地址仍为 ELF VA，不是完整 BPA-X 流水线输入。

实际参考对照命令：

```bash
PYTHONPATH=src uv run --locked python tests/compare_m3_bpax.py \
  tests/fixtures/binaries/test_64 --output outputs/m3_compare/test_64
PYTHONPATH=src uv run --locked python tests/compare_m3_bpax.py \
  tests/fixtures/binaries/test_32 --output outputs/m3_compare/test_32
```

脚本在独立进程运行 BPA-X 自己的 `gen_facts.py`，将双方表达式 ID 替换为结构后，比较关系多重集合及依赖结构，而非只比较数量。报告为 `comparison.json`。默认参考路径沿用本机约定，可通过 `--bpax-root`、`--reference-python`、`--readelf-bin` 修改。

此对照脚本目前要求 ELF VA 与 mapped VA 相同。PIE 地址约定由专项测试验证，尚未实现跨基址的 BPA-X 对照转换。未运行 M4 分块或最终指针求解器。

## 8. 状态与限制

- `status=complete` 表示 M2 块均完成范围一致的提升，不代表所有操作均有分析语义。未建模操作必须结合诊断读取。
- 提升失败或范围/jumpkind 不一致时保留块和错误诊断，manifest 标记 `partial`，CLI 返回 2；输入不一致时拒绝提取。不能将 partial 产物当作完整分析输入。
- 按约定参考 BPA-X 的支持范围，不新增 GetI/PutI、Dirty、CAS、LLSC、Triop/Qop 等操作的语义模型；非整数形式的浮点常量也标记未建模。CCall 保留条件依赖结构，未建模其求值。
- 当前事实在内存中构建，再写磁盘；已完成上述 bzip2 六样本的提取及产物检查，尚未进行大型二进制的内存占用或性能验收，也未跑 bzip2 的 BPA-X M3 对照。
- 本阶段不生成 SSA、不划分对象内存块，也不求解间接调用目标；已有未解析状态继续保留。
