# M1：ELF 加载与基础信息提取

状态：已完成。整理日期：2026-11-18。

本文记录本项目第一阶段的实现过程、接口、产物与验收结果。阶段编号采用本项目的 M1–M7 划分，M1 的职责是为后续 CFG、VEX 和指针分析提供统一的二进制加载信息。

## 1. 阶段目标与范围

输入为带 `PT_LOAD` 映射的 `ET_EXEC` 或 `ET_DYN` ELF。主要验证架构为 X86 和 AMD64。输出包括 ELF 元信息、符号与链接信息，以及可供后续阶段使用的地址转换和虚拟内存读取接口。

加载器使用 CLE 9.2.173，与本机 BPA-X 的加载依赖版本一致；采用 `auto_load_libs=False`，由 CLE 执行受支持的重定位。依赖库只记录名称，不自动加载其真实代码。

本阶段不构建 CFG，不恢复函数范围，不生成 VEX facts，也不进行对象内存分块、SSA 或间接调用求解。ELF 入口不等同于 `main`，可执行区域不等同于已确认指令，符号表也不等同于完整函数清单。

## 2. 实现过程

1. **建立最小 ELF 读取模块。** 使用 pyelftools 读取 ELF 头、加载段和节区，定义独立数据模型，并提供命令行 JSON 输出。
2. **固定测试输入。** 使用本地 GCC 13.3.0 将同一个 `test.c` 编译为 `test_64` 和 `test_32`；通过软链接接入公共目录中的 bzip2 样本。
3. **核对与 BPA-X 的加载差距。** 在元信息读取基础上，补充符号、导入、依赖、PLT、重定位和加载后内存访问需求。
4. **接入 CLE 并完善数据契约。** 使用同一份 ELF 字节快照进行解析、哈希计算和加载；对外返回项目自己的模型，增加 ELF 地址与映射地址的区分，将 JSON 升级为 schema 2。
5. **修复审查发现的问题。** 增加输入/输出文件身份检查，防止硬链接或符号链接覆盖输入；对输出使用临时文件加替换的方式发布；校验有文件内容的节区是否越界，正确排除 `SHT_NOBITS` 等情况。
6. **完成验收。** 运行自动测试、与 BPA-X 加载入口对照，并使用原有 BPA-X 辅助脚本比较区域及原始全局数据产物。

核心处理顺序为：

```text
ELF 文件
  → 读取字节快照、检查 ELF 元信息
  → CLE 加载、映射和重定位
  → 提取符号、导入、依赖、PLT、重定位及区域
  → BinaryInfo 数据模型
  → binary.json / LoadedBinary 内存读取接口
```

## 4. 主要产物：binary.json

常规保存位置为 `outputs/<样本名>/m1/binary.json`。文件使用 schema 2，主要内容如下：

| 类别 | 字段 | 用途 |
| --- | --- | --- |
| 输入身份 | `path`、`sha256`、`file_size` | 将后续结果绑定到同一个 ELF |
| 格式与架构 | `elf_type`、`machine`、`arch`、`bits`、`endianness` | 确定机器架构和数值解释方式 |
| 地址 | `entry`、`mapped_entry`、`linked_base`、`mapped_base`、`load_bias` | 区分原始与映射后的地址 |
| 内存布局 | `segments`、`sections` | 保存文件偏移、地址、大小及权限/标志 |
| 区域 | `executable_regions`、`global_regions` | 定位代码候选区及全局数据区域 |
| 符号 | `symbols` | 名称、类型、大小、导入/导出/弱符号标志及适用地址 |
| 导入与依赖 | `imports`、`dependencies` | 导入槽、目标、解析状态及依赖库名称 |
| PLT 与重定位 | `plt`、`relocations` | 保存跳板地址、重定位位置、符号和解析状态 |
| 加载策略 | `loader_backend`、`loader_version`、`auto_load_libs` | 记录加载实现和依赖库加载策略 |
| 数据契约 | `schema_version`、`address_space` | 供下游检查格式版本和地址含义 |

地址以 JSON 整数保存。`address_space: elf-va` 表示段、节区、区域及 `entry` 使用原始 ELF 虚拟地址；字段名含 `mapped` 的地址使用 CLE 映射地址。对主 ELF：

```text
load_bias = mapped_base - linked_base
mapped_address = elf_address + load_bias
```

区域采用左闭右开区间 `[start, end)`。未定义、绝对值和 TLS 符号不伪装成普通主 ELF 地址。`target_is_extern` 为真时，目标是 CLE 分配的外部占位地址，不是已加载库函数的真实代码地址。

`global_regions` 对应 `.data*`、`.bss*` 和 `.rodata*` 区域，不是后续 BPA 的对象内存块。缺少 `.symtab` 或 DWARF 不会直接导致加载被拒绝。

## 5. 内存接口与阶段交接

```python
from bpa.loader import load_elf, open_elf
from bpa.model import BinaryInfo

# 元信息可保存为 JSON，也可从 JSON 字典恢复。
info = load_elf("tests/fixtures/binaries/test_64")
restored = BinaryInfo.from_dict(info.to_dict())

# 需要程序字节时，持有加载结果并使用映射地址读取。
loaded = open_elf("tests/fixtures/binaries/test_64")
address = loaded.to_mapped(loaded.info.entry)
data = loaded.read_memory(address, 16)
```

- `load_elf()` 返回 `BinaryInfo`；`open_elf()` 返回带 `.info` 的 `LoadedBinary`。
- `read_memory()` 读取重定位后的映射内容，包含 BSS 初始零值；不执行程序，不产生运行后的变量值。
- `to_mapped()`、`to_elf()` 用于主 ELF 地址转换，不将外部占位地址转换成主 ELF 地址。
- PIE 可通过 `mapped_base` 或 CLI 的 `--mapped-base` 指定基址，该参数只接受 `ET_DYN`。
- 文件读取失败使用 `OSError`，ELF 解析/加载失败使用 `ELFLoadError`，非法或不完整内存读取使用 `ValueError`。

JSON 不嵌入完整内存镜像。后续阶段读取 `binary.json` 获取结构信息，需要字节时重新加载相同 SHA256 的 ELF，并保持记录的加载策略和映射基址。加载器内部 CLE 对象不作为阶段间的数据契约。
